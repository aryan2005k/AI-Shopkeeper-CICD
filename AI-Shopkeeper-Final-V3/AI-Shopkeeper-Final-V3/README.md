# AI Shopkeeper — AI-Based Demand Forecasting & Smart Inventory Management (V3)

Small-retail decision-support system: **sales history → ML forecast → explanation → reorder recommendation.**

## Quick start (Windows)

```bat
setup.bat      :: once: virtual environment + packages (+ optional TensorFlow)
run.bat        :: every time: starts http://127.0.0.1:8000
```

Manual: `python -m venv .venv`, `.venv\Scripts\activate`, `pip install -r requirements.txt`,
`python -m uvicorn backend.app:app`. LSTM experiment (optional): `pip install -r requirements-lstm.txt`.
Python 3.11 or 3.12 is recommended; use `requirements-lock.txt` to reproduce the exact tested versions.

> The bundled data are **synthetic**. For the final report, import a real dataset and state its source
> (e.g. Kaggle "Store Item Demand Forecasting", "Rossmann Store Sales" or M5 Walmart): map its columns to
> `date, product_id, product_name, category, quantity_sold, unit_price, promotion`, then run
> `python scripts/import_csv.py your_file.csv --reset` (or use the Upload button).

Re-uploading a CSV updates existing (date, product) rows; it never duplicates them.
Days with no row are treated as zero demand.

## Methodology

1. **Features (16):** calendar (day-of-week, week, month, quarter, weekend), lags (1, 7, 14, 28), rolling mean (7/14/28) and std (28) computed on past data only (`shift(1)` → no leakage), unit price, price change, promotion.
2. **Models compared per product:** Moving Average (7d), Seasonal Naive (7d), Random Forest, LightGBM. The LSTM (TensorFlow) is a separate experiment evaluated on the *same* hold-out window.
3. **Validation (all chronological, never shuffled):**
   - 80/20 hold-out → MAE, RMSE, WAPE (one-step-ahead);
   - expanding-window `TimeSeriesSplit` cross-validation on the training period → used to **select** the model (so the hold-out is not used for selection) and for optional hyper-parameter tuning;
   - 7-day **recursive back-test** over the hold-out → WAPE that matches how multi-day forecasts are really produced.
4. **Production model:** the selected model is **re-fitted on 100 % of the history**, cached on disk, and only re-trained when the sales data change (or "Retrain models" is ticked).
5. **Explainability:** SHAP `TreeExplainer` (mean |SHAP|) for the selected tree model, with a feature-importance fallback.
6. **Prediction interval:** approximate 80 % range from the 7-day back-test error.
7. **Inventory rules:** `reorder = max(0, forecast + safety − stock − incoming)`; status ∈ {Stockout Risk, Overstock Risk, Reorder, Monitor, Healthy Stock}. A statistical safety-stock suggestion `z · σ_daily · √lead-time` is shown next to the stored value.

**Metrics:** MAE = mean |error|; RMSE = √mean(error²); WAPE = Σ|error| / Σ|actual|.

## Reproducing the results table for the report

```bat
python scripts\benchmark_all.py            :: all products, all standard models
python scripts\benchmark_all.py --tune     :: with hyper-parameter search
python scripts\benchmark_all.py --lstm     :: also the LSTM (needs TensorFlow)
```
Output: `results/model_comparison.csv` plus a summary. Every run is also logged in the `model_results`
table (`/api/results`, `/api/results.csv`, or the "Download results" button).

## What changed in V3

- Fixed duplicate sales when a CSV is uploaded twice (unique key + safe upsert; old databases are cleaned automatically).
- Models are trained once and cached; final model is refitted on all data (previously trained on 80 % only and retrained on every click).
- Calendar gaps no longer shift the lag features; missing days are filled.
- Model selection uses time-series cross-validation; optional tuning; stronger Seasonal-Naive baseline; baselines evaluated one-step-ahead like the ML models (fair comparison); 7-day recursive back-test.
- LightGBM `min_child_samples` lowered (the default of 20 prevented splits on small data).
- LSTM: same hold-out window as the tree models, early stopping, cached model, results logged and shown side by side.
- Prediction intervals, statistical safety-stock suggestion, results logging/export, data warnings.
- Faster bulk CSV import; offline-safe charts (local Chart.js → CDN → built-in canvas fallback); loading indicators; pinned/locked requirements; launcher scripts.

## Limitations (state these in the report)

- The bundled dataset is simulated; conclusions about real shops need real data.
- Multi-day forecasts are recursive, so error grows with the horizon (see the 7-day column).
- Future promotions/prices are unknown at forecast time; the model assumes no promotion and the last known price.
- Missing dates are assumed to be zero demand (e.g. closed days) — stock-outs that hide true demand are not modelled.
- The LSTM uses sales history only (no price/promotion inputs) and is not part of automatic model selection.
- Per-product models; no cross-product learning, no supplier/lead-time management beyond the safety-stock formula.
